# Приватность и безопасность

Этот документ описывает технические границы текущей версии проекта. Он не является
юридической политикой конфиденциальности, обещанием абсолютной анонимности или списком
непубличных деталей защиты.

## Данные и границы

Проект обрабатывает текст резюме и его обезличенную версию. Для будущих сценариев также
предполагаются текст вакансии, заметки пользователя и сгенерированные черновики.

```text
Источник резюме
  -> проверка формата и размера
  -> извлечение текста
  -> source text + редактируемая обезличенная версия
  -> явное подтверждение пользователя
  -> будущий LLM workflow использует только подтверждённую версию
```

Техническое обезличивание снижает распространение прямых идентификаторов, но не является
юридически гарантированной анонимизацией. Пользователь просматривает и подтверждает
обезличенный текст до его возможного использования в AI-сценарии.

Текущее подтверждение относится только к конкретной проверенной обезличенной версии.
Интерфейс ссылается на честную placeholder-страницу: политика обработки персональных
данных ещё готовится, а действие не выдаётся за юридическое согласие или иной правовой
документ.

## Реализованные меры

### Доступ к данным

- Защищённые API-маршруты используют серверную сессию.
- Регистрация, вход, восстановление доступа и logout выполняются через Better Auth;
  web-клиент не хранит долгоживущий auth token и передаёт cookie только браузером.
- Операции с резюме на сервере ограничены владельцем записи через `userId`.
- Контракты API для резюме не возвращают исходный текст резюме.
- Тесты проверяют, что пользователь не может прочитать, изменить, подтвердить или удалить
  запись другого пользователя.

### Ввод и загрузка файлов

- Поддерживаются только файлы PDF, MD и TXT.
- До извлечения проверяются размер, MIME-тип и расширение файла.
- Пользовательский путь не используется как путь файловой системы.
- Временный upload buffer очищается после извлечения текста.
- Извлечённый текст ограничивается по размеру, чтобы снизить риск чрезмерного ввода.

### AI и диагностика

- Исходный текст резюме не предназначен для передачи в LLM.
- Production prompts не входят в tracked-код и не передаются во frontend или
  диагностические ошибки.
- Публичный mock mode предназначен только для воспроизводимых тестов и не выдаётся за
  результат реальной модели.
- Пользовательские тексты, секреты, cookies и ключи не должны попадать в логи.

### Публичный репозиторий

Файлы разделяются на `PUBLIC`, `PRIVATE`, `SECRET` и `GENERATED`. Автоматическая проверка
перед commit/push блокирует закрытые, секретные и не классифицированные tracked-файлы, а
также распространённые форматы секретов. Она дополняет, но не заменяет ручной review.

Подробности для участников разработки приведены в [SECURITY.md](../SECURITY.md).

## Планируемые меры

Следующие пункты относятся к целевой архитектуре и ещё не являются реализованной
функциональностью:

- асинхронные AI-jobs получают только идентификаторы, а не полные пользовательские тексты;
- идемпотентность фоновых заданий предотвращает повторное списание квоты и дублирование
  результата;
- будущие маршруты с пользовательскими данными получают проверки IDOR, CSRF, XSS,
  oversized input, prompt injection, rate limit и race condition;
- auth-flow использует httpOnly cookie, подтверждение email и отзыв сессий при
  восстановлении доступа; настройка `Secure`, SameSite и CSRF-защиты для внешнего
  production-запуска требует отдельной проверки конфигурации deployment;
- перед внешним production-запуском потребуется отдельный privacy/legal review.

## Ответственное раскрытие

Если вы нашли уязвимость или случайно опубликованный секрет, не создавайте публичный
issue с подробностями. Свяжитесь с владельцем репозитория приватным каналом, указанным в
профиле репозитория, и приложите минимально необходимое описание для воспроизведения.

При подтверждённой утечке секрета приоритетный порядок действий: отозвать секрет,
ограничить доступ, переписать затронутые Git refs при необходимости и только затем
публиковать исправление. Удаление секрета новым commit само по себе не очищает историю.

## Как поддерживать документ

Документ обновляется в той же задаче при изменении модели данных, trust boundary,
аутентификации, публичного поведения AI-workflow или защиты репозитория. Новые типы
данных и файлов сначала получают явную классификацию; если решение влияет на риск,
оно согласовывается с владельцем до публикации.
