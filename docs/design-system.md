# Дизайн-система

## Назначение

Текущий web-клиент оформлен как спокойная рабочая поверхность: пользователь вводит и
проверяет резюме, создаёт вакансию и запускает анализ, а интерфейс делает состояние данных и действия понятными без лишней
декоративности. Это описание фиксирует реализованные общие правила, а не обещает
неизменность будущего визуального направления.

## Принципы

- **Рабочий контекст прежде декора.** Основное действие, состояние подключения и ошибки
  видны без необходимости искать их в интерфейсе.
- **Одна визуальная система.** Цвета, интервалы, типографика, радиусы и motion берутся из
  общих CSS-токенов, а не подбираются заново для каждого компонента.
- **Содержимое важнее контейнера.** Светлый фон, тонкие разделители и умеренная тень
  отделяют панели, не конкурируя с текстом и полями формы.
- **Состояние не скрывается.** Loading, empty, success, error, disabled и connection state
  имеют отдельное визуальное представление.

## Токены

Источник реализованных токенов — [`tokens.css`](../tokens.css).

| Категория | Токены и применение |
| --- | --- |
| Поверхности | `--color-paper`, `--color-paper-raised`, `--color-paper-muted` для фона, панелей и неактивных состояний. |
| Текст и границы | `--color-ink`, `--color-ink-muted`, `--color-ink-subtle`, `--color-rule`, `--color-rule-strong`. |
| Семантические состояния | `--color-accent`, `--color-success`, `--color-warning`, `--color-danger`, `--color-focus`. Цвет дополняется текстом, границей или формой элемента. |
| Типографика | `--font-display` для заголовков, `--font-body` для основного текста, `--font-mono` для коротких технических меток и статусов. |
| Интервалы | Шкала `--space-3xs` … `--space-4xl`; компоненты используют её вместо произвольных отступов. |
| Геометрия | `--radius-input`, `--radius-card`, `--radius-pill`, `--rule-width`, `--shadow-raised`. |
| Движение | `--dur-fast`, `--dur-base`, `--dur-slow` и easing-токены для короткой обратной связи. |

## Компоновка и адаптивность

Основной контейнер ограничен читаемой шириной. Рабочая область библиотеки резюме строится
в две колонки: форма и список. При ширине до `48rem` она переходит в одну колонку; при
ширине до `30rem` групповые действия становятся вертикальными, а основные кнопки могут
занимать всю доступную ширину.

Панели используют одинаковые границу, фон, радиус и лёгкую тень. Поля формы имеют
явные label, вспомогательный текст и состояние disabled. Для длинного пользовательского
текста включён перенос, чтобы содержимое не выходило за границы карточки.

## Состояния и доступность

- Интерактивные поля и кнопки используют `:focus-visible` с заметным focus outline.
- Кнопки и поля сохраняют обычный курсор и понятный внешний вид в disabled-состоянии.
- Ошибки формы и подключения выделяются семантическим цветом и текстом; успешное
  подтверждение также имеет отдельную метку.
- Вёрстка не зависит от hover как от единственного способа получить информацию.
- При `prefers-reduced-motion: reduce` переходы сокращаются, а прокрутка становится без
  анимации.

Дальнейшие UI-изменения должны сохранить эти базовые свойства и проверять ключевые
состояния с клавиатурной навигацией. При создании новой страницы, изменении layout или
визуальном редизайне применяется локальный процесс визуального проектирования проекта.

## Как поддерживать документ

Документ обновляется вместе с задачей, если меняются общие токены, типографика,
адаптивная компоновка, правила состояний, доступности или motion. Он описывает только
реализованный UI; нереализованные брендовые и продуктовые планы сюда не переносятся.
