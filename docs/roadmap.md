# Публичный roadmap

Roadmap показывает направления развития portfolio-проекта, а не обязательства по
срокам, бюджету или коммерческой стратегии. Статус реализованных возможностей указан в
[спецификации продукта](product-spec.md).

## Now

- Поддерживать воспроизводимую локальную разработку: build, тесты и безопасный mock mode.
- Развивать библиотеку резюме с серверной проверкой владельца, редактируемой
  обезличенной версией и подтверждением пользователя.
- Поддерживать явные публичные/закрытые границы материалов и проверку перед commit/push.
- Поддерживать результаты public-release audit: проверять историю, clean clone,
  Docker artifacts и GitHub security controls перед значимыми изменениями публикации.
- Документировать фактическое состояние кода в тех же задачах, которые его меняют.

## Next

- Добавить vertical slice вакансии: безопасный ввод, выбор подтверждённого резюме и
  snapshot обезличенной версии.
- Перенести запуск initial AI workflow в асинхронную модель с явными статусами run и
  отображением прогресса.
- Сохранить результат анализа и пользовательскую редакцию раздельно, не меняя без
  отдельной задачи смысл legacy Markdown-результата.
- Подготовить отдельные управляемые workflows для HR-подготовки и post-interview разбора.

## Later

- Развить модульный монолит worker-компонентом и очередью задач.
- Добавить безопасную историю вакансий, квоты и идемпотентное выполнение фоновых jobs.
- Перед внешним запуском проверить production-конфигурацию auth: `Secure`/SameSite cookie,
  CSRF-защиту и rate limit на фактическом deployment.

## Явно вне scope сейчас

- Автоматическая отправка откликов, писем, сообщений в Telegram или изменение внешних
  профилей от имени пользователя.
- Свободный AI-чат вместо ограниченных сценариев.
- Публичная публикация production prompts, реальных пользовательских данных и
  evaluation-материалов.
- Обещание трудоустройства, безошибочности AI или готового production deployment.

## Как поддерживать документ

Пункты перемещаются между разделами только после подтверждённого изменения кода или
продуктового решения. Здесь не фиксируются даты, бюджеты, внутренние исследования или
детали конкурентной стратегии. Если новая работа меняет публичный статус функции или
приоритет направления, roadmap обновляется в той же задаче.
